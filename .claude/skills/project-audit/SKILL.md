# Unity 專案盤點

## 目標

根據實際檔案與可驗證結果建立可信的專案現況，找出最重要的下一步。此任務以分析與文件更新為主，不要順便重構遊戲。

## 步驟

1. 閱讀根目錄 `CLAUDE.md` 與 `Documentation/` 中的文件。
2. 檢查 Unity 版本、套件、目錄結構、場景、主要腳本與資產類型。
3. 追蹤入口場景、核心玩法、管理器、資料流與場景切換方式。
4. 若可用，檢查編譯錯誤、Console、測試與 MCP 工具能力；明確區分「已實際驗證」與「僅從程式碼推測」。
5. 將功能分類為已完成、部分完成、未開始、有問題或待確認。
6. 找出重複系統、缺失引用、明顯風險與阻擋開發的問題。
7. 更新 `Documentation/CURRENT_STATUS.md`、`PROJECT_ARCHITECTURE.md` 與 `DEVELOPMENT_ROADMAP.md`。
8. 如果發現玩法規格無法從專案確定，將問題記入 `GAME_DESIGN.md` 的待確認區，不要自行編造答案。

## 限制

- 不要大規模修改遊戲程式。
- 不要刪除、移動或覆蓋資產。
- 不要把未執行的測試寫成通過。
- 不要把不存在的 MCP 工具描述為可用。
- 不要在未經確認下選擇付費生成服務。

## 完成回報

提供：
- 專案實際狀況摘要
- 主要架構與入口位置
- 已完成／部分完成／未完成項目
- 重要錯誤與風險
- 最重要的 1–3 個下一步及其完成條件
- 已更新文件與未能驗證的部分
