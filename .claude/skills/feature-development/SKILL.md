# Unity 功能開發流程

## 1. 確認需求

- 用簡短文字重述功能目標與完成條件。
- 找出相關腳本、Prefab、場景、資料、事件與測試。
- 閱讀相關架構與決策文件。
- 區分必須完成的需求與可選改善。

## 2. 設計最小修改

- 優先沿用現有架構與命名方式。
- 說明預計修改的檔案與原因。
- 找出可能影響的其他系統。
- 高風險或需求不清楚時，先詢問使用者；低風險且目標清楚時可直接進行。

## 3. 實作

- 一次處理一個可驗證的功能切片。
- 避免無關重構與重複建立系統。
- 保留既有序列化欄位、Prefab 引用與資產 GUID。
- 不要用刪除功能、停用測試或忽略錯誤來掩蓋問題。
- 若需要新增資產，先搜尋是否已有可重用資產。

## 4. 驗證

依環境可用性進行：
- 程式碼與引用檢查
- 編譯／測試
- Unity 場景、Prefab、Inspector 與 Console 檢查
- 核心流程與錯誤情境測試

清楚標示哪些項目已實際測試，哪些只是靜態檢查。

## 5. 更新文件

更新 `CURRENT_STATUS.md`；若架構、玩法規則或重要決策改變，也更新對應文件。

## 6. 回報

以繁體中文列出：
- 修改結果
- 修改檔案
- 驗證方式與結果
- 未完成項目與風險
- 下一步（如有必要）
