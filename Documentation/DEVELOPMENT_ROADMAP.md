# 開發路線圖（Development Roadmap）

> 本文件是規劃，不是已完成清單。首次盤點後，先依賴關係與風險排序，不要一次建立過多不確定的任務。

## 優先級定義

- **P0：** 阻擋專案開啟、編譯、核心玩法或主要流程的問題。
- **P1：** 完成最小可玩流程所必需的功能。
- **P2：** 提升體驗、內容量、可讀性與穩定性。
- **P3：** 非必要的 polish、實驗功能或長期優化。

## 排序規則

1. 先處理會阻擋其他工作的問題。
2. 優先選擇能完成一段完整使用者流程的任務。
3. 對不確定或高風險任務先做小型驗證。
4. 不要只因為某功能容易做，就忽略更重要的依賴。
5. 每完成一項任務，更新狀態、驗證結果與下一步。
